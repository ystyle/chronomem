## 摘要

长周期运行的 Agent（跨周、跨月地持续工作：迭代一个代码库、写一篇论文、长期维护一个项目）需要一个根本性的能力：记住很久以前发生的事。但今天的 Agent 外部记忆系统要么是「扁平存储」（全存下来、按近因/相似度检索），要么是「一次性压缩」（定期把整段对话压成一份报告）。前者不提供任何压缩：过了几个月，没有任何一层能告诉你「这一阵子大概发生了什么」；后者破坏证据：决定被记住了，但「为什么、怎么做的」——那些原始事件——丢了，且无法重新推导。

忆时塔（Chronomem，「记忆时间之塔」）旨在占据中间地带，我们称之为**时间分层记忆（time-layered memory）**：把事件记录组织成一张**随时间分层的物化快照层级**——从 10 分钟到一周——每一层既是(a)指向更细层、最终指向原始记录的**导航结构**，又是(b)可一眼读懂的**可选语义摘要**。这模仿了财务会计从原始账本逐层物化季报的做法：账本永不删除、报表渐进重算、每张报表都能审计回底层条目。

我们把忆时塔做成一个 **MCP（Model Context Protocol）服务**——一个常驻守护进程，任何支持 MCP 的客户端（opencode、Cherry Studio、自定义 Agent 等）都能接入。我们主张：把记忆做成**协议**而非私有库，本身就是一个系统层面的贡献——它让异构工具在零代码耦合的前提下共享同一个记忆底座。

本文是一篇 **position（定位）与设计**论文：我们从认知科学类比（记忆巩固）出发论证设计动机，把它与当前 LLM 记忆系统的相关工作对齐，陈述区分本方案的双轨成本模型，并列出计划用实证回答的开放问题。

## 1. 引言

Agent 在长时间尺度上工作，遇到的根本限制是：上下文窗口有界，而值得记住的事件无界。现有方法分成两派，各自有相反的失败模式：

- **扁平外部记忆**（全存，按近因或相似度取回）：保留了细节，但没有压缩——几个月后，没有任何层级能一句话告诉你「这段时间发生了什么」，除非把全部内容读一遍。
- **一次性压缩**（定期把整个会话压成一份报告）：破坏了证据——决定被记住了，但「为什么、为什么选它、怎么做的」这些原始事件没了，且无法重新推导。

忆时塔的设计目标正是这两者的中间态。在时间上分层、物化：每一层同时是「导航结构」（引用更细层直到原始记录）和「可选语义摘要」（一眼可读）。这与财务会计的季报-账本结构同构：**账本永不删，报表渐进算，报表可审计**。

我们将忆时塔暴露为 **MCP 服务**——一个常驻守护进程，任何 MCP 客户端都能接入。把记忆做成**协议**而不是私有库，我们认为是系统层面的贡献：让异构工具共享一个记忆底座，而不需要代码耦合。

本文定位为**设计/观点论文**：从记忆巩固的认知类比出发论证设计动机，与 LLM 记忆系统的工作对齐，陈述「双轨成本模型」这一核心主张，并列出拟用实证回答的开放问题。

## 2. 背景与相关工作

**认知科学中的记忆巩固。**「近期记忆随时间被渐进重组为更粗、更持久的形式」是广为接受的人类记忆机制（巩固 consolidation；睡眠相关的重放 replay）。我们的「分季财报式」物化是其工程化类比：新记录保留细粒度，粗粒度摘要渐进物化而不删除细层。我们只引用它作为灵感，不主张任何生物意义上的保真。

**时序数据库与 rollup。** 分层时间窗 + 物化聚合在时序数据库中是标配（rollup / 连续聚合 / 降采样，如 TimescaleDB 连续聚合、Prometheus 降采样）。忆时塔复用了这套机制（基于 `tsdb` 库），但向数据库不做的方向扩展了一层：粗层不仅是数值聚合，还可以是**对任意 JSON 事件生成的 LLM 语义摘要**。

**LLM 记忆系统。** 为 LLM Agent 提供长期记忆的研究正在快速增长：MemGPT（Packer 等）引入分层上下文管理与记忆层级；Generative Agents（Park 等）把「记忆流」与检索、反思结合；A-MEM 与 Mem0 发展出 agentic / 组织化的记忆；**HiMem**（arXiv:2601.06377）为长周期 Agent 提出分层长期记忆；**RaMem**（arXiv:2606.22844）研究情境重激活；**AriadneMem**（arXiv:2603.03290）处理 Agent 的终生记忆。我们的差异点在于：(i) 把「精确回想」（零 token、走引用链）与「语义回想」（LLM、压缩）作为**显式的成本模型**分开；(ii) 摘要是**一等公民的时序条目**，可被递归再总结；(iii) 把整个底座标准化在 MCP 接口后面。

**主题记忆 vs 时间记忆。** 「LLM wiki」一类系统（如 LLM WIKI；*Beyond RAG: LLM Wikis as Living Semantic Memory*，Zenodo 20078453）按主题/语义词条组织知识——主题记忆，类比维基百科。忆时塔按时间组织——时间记忆，类比账本。二者互补：时间日志可沉淀出主题词条，词条可回溯到时间证据。我们把这个对比讲清楚，是因为我们相信很多「记忆」系统混淆了两条轴，而轴的选择应跟随用途：论文是「过程」（时间），参考手册是「知识体」（主题）。

**Model Context Protocol。** MCP（modelcontextprotocol.io）标准化了客户端与服务器之间的工具、资源与提示。忆时塔在此的贡献是：把**记忆**作为一等 MCP 能力（`mem/*` 工具集 + `mem://` 资源），让任何 MCP 客户端无需集成私有 SDK 即可采用共享、演化的记忆。

## 3. 设计总览

忆时塔是一个独立的守护进程，只提供一个 streamable-HTTP MCP 端点。存储是单一时序数据库（`tsdb`），每个记忆类型一个 series。设计有五大支柱：

**P1——记忆类型由用户自定义。** 一个*类型*是一条带名字的 series，含可选描述与 schema（供文档与 LLM 提示用，不强制校验）、可选保留期，以及*粒度链*（见下）。客户端可建 `work/chat`、`paper/decisions`、`tool/errors` 等类型。类型名白名单（`[A-Za-z0-9_/-]`），防路径穿越。

**P2——类型级粒度链。** 每个类型声明自己的物化层级，从 {10min, 30min, 1h, 3h, day, week, month} 中取，默认为 10min→30min→1h→day→week。高频通道保留分钟级层级以支持**当天内精确回想**；稀疏通道（如一天一条的工作日志）用 day→week，避免建大量近乎为空的细桶。week 是默认的语义总结封顶：一整年的周级摘要只有约 52 条，加载便宜，且整年回忆极少需要。

**P3——三种物化模式。** 一个塔层可以用三种方式物化，成本不同：

| 模式 | 塔层内容 | 支持的回想 | LLM 成本 |
|---|---|---|---|
| 引用链（默认，事件型） | `PointRef`/`BucketRef` 指向更细层 | 精确下钻 | 零 |
| 数值聚合（可选，指标型） | count/avg/min/max JSON | 概览 + 下钻 | 零 |
| 语义摘要（可选，LLM） | LLM `SummaryRecord` | 语义回顾 | 有 |

**P4——双轨回想。** 两个读操作，成本差异明确：
- `mem/recall mode=exact`：沿引用链走到**原始条目**——无损、零 LLM token，但返回的是原始体量（引用链是**导航**，不是**压缩**）。
- `mem/recall mode=summary`：返回窗口的**语义摘要**——这才是真正压缩粗窗口的形态，且**依赖摘要已生成**（此前经 `mem/summarize`，或 `summarize_on_miss=true` 时按需现算）。

**P5——摘要是时序记录的一等公民。** `mem/summarize` 读一个窗口（按粒度+锚点，或按显式 `from/to` 处理不规则的「任务阶段」窗口），让 LLM 生成结构化摘要（锚点章节：决策/结论/待办/状态变更/关键词），并追加一条 `SummaryRecord {ts, windowFrom, windowTo, model, refs, text}` 到该类型的 `.summary` series。因为摘要本身是时序条目，可被再次总结：原始 → 10min 摘要 → 1h 摘要 → day 摘要，就是结构塔的语义对应物，实现**递归、非破坏的压缩**。`recompute` 标志可强制从原始条目重算，以控制语义漂移。

## 4. 双轨成本模型

我们的核心概念主张是：**回想不能被当成单一操作**。要区分：

- **精确回想 = 零 token 的导航。** 可靠、无损，但信息量就是原始体量；粗层的精确回想会把全部内容都取回来，不提供任何压缩收益。这是**导航**，不是**总结**。
- **语义回想 = 读摘要。** 这是唯一真正满足「窗口越粗、答案越小」的形态。但它有一个硬**前提**：摘要必须存在（之前生成过，或现在生成、花 LLM 成本）。因此，「回想零 LLM」**只对精确下钻成立**；粗粒度概览式回想本质上是依赖总结的。

这个区分回过头看很平凡，但我们认为现有系统把它模糊了，并由此产生三个具体后果：

1. **触发策略。** 只物化*结构*（引用链、聚合）的调度器可以每分钟跑、零 token 成本；而自动物化*语义摘要*的调度器会在空窗口或低价值窗口上悄悄烧 token。因此忆时塔默认**从不自动语义总结**：`mem/summarize` 手动调用，或按任务阶段边界调用；「摘要缺失」路径是显式的（`summarize_on_miss`）。
2. **语义漂移。** 对摘要再总结很便宜但会漂移；从原始数据重算保真但昂贵。把两者都暴露出来、用显式的 `recompute` 切换，把一个静默的质量问题变成调用方可控的权衡。
3. **上下文卫生。** 服务只存和取，从不主动把内容塞回客户端上下文。是否取回、取回多少，由客户端决定，从而守住「恒定上下文」的纪律。

## 5. 开放问题

- **语义漂移的量化。** 摘要链多久会偏离底层事件？什么时候 `recompute` 值回 token？我们计划用一组固定的探针问题测量沿链的信息保持度。
- **受 token 预算约束的触发。** 给定 token 预算，摘要应该主动算（如每小时/每周末）还是按需惰性算？这是关于 {窗口, 价值, 成本} 的优化问题。
- **保留与隐私。** MVP 全量存 payload、无隐私分级；类型级隐私/加密是后续工作——动机是记忆越积越敏感。
- **评估方法论。** Agent 记忆评估还不成熟。我们提议：固定长周期任务套件、带真值答案的查询集、指标 {回想精确率/召回率、token 成本、时延}，对比基线 {扁平近因记忆、一次性压缩、MemGPT 式记忆层级}。

## 6. 评估计划（待进行）

实证结果超出本文 position 论文的范围，将出现在后续论文中。计划中的研究：(i) 受控的长周期 Agent 任务（如跨模拟数周递增维护项目），对比忆时塔与扁平记忆、一次性压缩在回想准确率与 token 成本上的表现；(ii) 沿摘要链的语义漂移研究；(iii) 由作者开展的工作日志用例（day/week 粒度 + 任务阶段总结）定性研究。

## 7. 结论

我们呈现了忆时塔——一个基于 MCP 的时间分层外部记忆服务，其贡献是：(1) **双轨回想模型**，把零 token 的精确回想与依赖总结的语义回想区分开；(2) 摘要是**一等公民的时序条目**，支持递归、非破坏的压缩；(3) **类型级粒度链**，适配每个记忆通道自身的频率分布；(4) 把记忆做成**标准化的 MCP 能力**，跨工具共享。我们的主张不是生物保真、也不是任何单一组件在算法上的新颖——每个组件都借自数据库、记忆巩固理论或 LLM 记忆系统——而在于**组合本身**，以及「导航 vs 压缩」之间诚实的成本核算。这正是我们提出供讨论、并计划在未来实证验证的贡献。
